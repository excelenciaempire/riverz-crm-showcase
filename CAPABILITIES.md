# Riverz CRM: product and implementation map

Riverz CRM extends [wacrm](https://github.com/ArnasDon/wacrm). The inherited inbox, contacts, pipelines, campaigns and automation foundation remain credited to that project. This map adds the commerce and operations scope visible in the reviewed Riverz implementation.

| Area | Work represented |
| --- | --- |
| Commerce assistance | Merchant/product context, offers, objection answers, selected-product continuity, media delivery and human handoff |
| Product readiness | Shared product content, original and approved media, FAQs, coverage of buyer questions and revision-aware updates |
| Store and order operations | Product/order surfaces, store integrations, logistics and return workflows, with account-specific provider requirements |
| Merchant/team operations | Onboarding, roles, approvals, activity, operating guidance and administrative surfaces |
| Channels and tools | WhatsApp workflows, Instagram/web-chat integration surfaces, channel setup and account-scoped assistant/MCP access |

## My contribution

The Riverz-specific work includes merchant-scoped guidance, product knowledge/media handling, commerce workflows, onboarding, integration recovery and the domain adaptations described in [Riverz Dealers and Riverz Ventas](VARIANTS.md).

## Operating boundaries

Each merchant's catalog, offer, shipping/payment rules and connections remain distinct. Media readiness means actual approved files, rather than a prompt or planned deliverable. A page or integration handler is not proof that a specific merchant's provider is authorized or that an order/payment action succeeded.

This map describes the product work and shared foundation without customer conversations, credentials or claims of provider-wide certification.
